Technical details

For people who want to know exactly how ATA works and why they can trust it. You don't need any of this to use ATA.

Source code and licence

The Android app, the Mac app, and the protocol specification are open source under the MIT licence, in one repository: github.com/magiclin99/ata. The protocol is in SPEC.md (currently written in Traditional Chinese), with test vectors in spec/vectors.json. Both apps have unit tests against those vectors. Security reports: see SECURITY.md in the repository.

  • Android: Kotlin and Jetpack Compose, Android 9 or later (minSdk 28). QR codes are decoded on the phone with the bundled ZXing library.
  • Mac: Swift and SwiftUI, macOS 14 or later, a universal build (Apple silicon and Intel).

How a transfer connects

  1. Discovery and signalling over Bluetooth LE. The Mac is a BLE peripheral. The phone connects and both sides run a mutual HMAC-SHA256 challenge-response with nonces from each side, keyed by the 256-bit pairing key. Per-direction session keys are derived with HKDF-SHA256. Every BLE message after that is AES-256-GCM with counter nonces.
  2. Path 1: local network. The Mac opens an ephemeral TCP port and sends its LAN IPv4 addresses over the encrypted BLE channel. The phone dials them, bound to its Wi-Fi network, and streams length-prefixed AES-256-GCM records.
  3. Path 2: direct peer-to-peer. If TCP fails, the phone sends a complete (non-trickle) WebRTC offer over BLE. ICE uses only the public STUN servers stun.l.google.com:19302 and stun.cloudflare.com:3478. TURN (a relay) is never configured. The DTLS fingerprints are authenticated because the SDP travels over the already-authenticated BLE channel.
  4. No path: the phone reports that it couldn't reach the Mac. There's deliberately no relay fallback, so on networks that block peer-to-peer (for example symmetric NAT on both sides) the transfer fails rather than going through a server.

Each file carries a SHA-256 that the Mac checks before renaming the temporary file into place. A mismatched or incomplete file is deleted. Measured: about 60 MB in around 6 s on the same Wi-Fi including discovery and handshake; around 1 MB/s peer-to-peer over mobile data.

Pairing keys and stored data

  • Pairing: the Mac shows a QR code holding its 16-byte device ID and a fresh 32-byte key, valid for 5 minutes and usable once.
  • Android stores the key encrypted with a non-exportable Android Keystore key, and app backup is disabled.
  • The Mac stores it in ~/Library/Application Support/io.github.magiclin99.ata.mac/pairings.json (folder mode 0700, file 0600, excluded from Time Machine backups).
  • The Mac advertises the local name ATA- plus the first 8 hex characters of its random device ID, which any nearby scanner can see.

The Mac installer and signing certificate

The Mac app isn't notarized (no paid Apple Developer Program membership). It's signed with one fixed self-signed certificate: mac-app/signing/ata-signing-cert.pem, SHA-1 3DA39545619D4949FA758C6BECC77F9E2E3CE65E, SHA-256 B7C994A86BB61C91BB8A2F94CBAA33B9BC1C7FE97E646CA3DF38A49E964C9387. If an "ATA" ever presents a different certificate, don't install it.

The one-line installer (curl -fsSL https://github.com/magiclin99/ata/releases/latest/download/install.sh | sh):

  1. Finds the latest release and downloads ATA-<version>.zip and its .sha256.
  2. Checks the SHA-256, then runs codesign --verify --deep --strict against a pinned requirement (bundle ID plus the certificate's SHA-1). Anything else is refused and nothing is installed.
  3. Quits a running ATA, replaces /Applications/ATA.app (asking for a password only if that folder isn't writable), and opens it.

Files fetched with curl get no quarantine attribute, so Gatekeeper doesn't prompt. To preview without changing anything: … | sh -s -- --dry-run. Read the script first: it's attached to every release and is in mac-app/install.sh.

Network use and privacy

  • No analytics, no crash reporting, no ads, no accounts, and no developer server. The apps send nothing to the developer.
  • The only third-party contact is the STUN request on the peer-to-peer path, which reveals the devices' public IP addresses and ports to Google or Cloudflare. Same-Wi-Fi transfers don't touch the internet.
  • The Mac app's "Check for Updates…" only opens the Releases page in your browser. There's no background update check.
  • Android permissions: BLUETOOTH_SCAN (declared neverForLocation) and BLUETOOTH_CONNECT; location only on Android 9–11 (required by the OS for BLE scans); CAMERA (only while scanning); INTERNET and network state; a foreground service of type connectedDevice; notifications.
  • Mac: Bluetooth, local network, an inbound listener (so the macOS application firewall may ask), notifications, and login items.

The full policy is the privacy policy.

How it compares

  • AirDrop is Apple's feature between Apple devices. ATA doesn't use or connect to it.
  • Cloud drives and chat apps upload your file to a company's server and keep a copy there. ATA sends directly and keeps no copy except on the Mac you sent to. The trade-off is that the devices must be within Bluetooth range.
